## Setting up Content Architecture (2026-06-14)

Today I completed one of the most critical infrastructures of the project: The content management system.

I decided to build a file-system based MDX architecture instead of using a database. The biggest advantage is being able to write my content directly in my code editor and version it with git. However, the biggest risk of working with Markdown is the lack of type safety.

To solve this:
1. I parsed the frontmatter using `gray-matter`.
2. I subjected this parsed frontmatter data to strict validation at build time using `zod`.

This way, if I enter a missing title or an invalid date, I am notified before the project even compiles. Goodbye to broken pages silently making their way to production.

## Day 1: Foundation and UI Construction (2026-06-14)

Today, we built the digital workspace named Epic Borg from scratch. Here is the summary of the day and the technical processes:

### 1. Foundation & Architecture
- Initialized a brand new project based on **Next.js 16 (App Router)**.
- Configured TypeScript and ESLint rules to maintain code quality.
- Established **Design System Tokens** (`tokens/colors.ts`, etc.) to centrally manage visual decisions.
- Configured global styles using the modern `@theme` directives of Tailwind CSS v4.

### 2. Advanced Infrastructure (MDX & i18n)
- Integrated **`next-themes`** to automatically detect user system preferences.
- Built a middleware and routing structure with **`next-intl`** to fully support Turkish and English localizations.
- Created a type-safe Markdown/MDX system using **`next-mdx-remote`** and **Zod** that performs build-time validation.

### 3. Design & UI Components
- **Letterpress business-card identity:** bone-coloured paper with a subtle paper-grain texture, blood-red ink (#8A0303, brightened to #E5484D in dark mode) and sharp corners, all defined as design tokens.
- **Typography:** Cormorant Garamond serif for headings and card text, with Geist for body text.
- Animations run on **CSS keyframes and native browser APIs**, with no animation library, and respect `prefers-reduced-motion`:
  - **Home planet:** A blind-embossed intro text sits at the centre of a drawn, tilted orbit with four business-card satellites. They rotate only on click, prev/next links, arrow keys or swipe, never on page scroll. On narrow screens they become one swipeable card.

### 4. Pages & Experience
- **Home:** The hero is a single centred business card with the name and role. Featured projects are shown as playing cards whose rank and suit are random on each load.
- **Projects:** Projects are pulled live from the GitHub API and dealt one by one from a deck as rounded playing cards when the page opens. The suit shows status (spades for completed, diamonds for nearly finished, hearts for active, clubs for other) and the rank follows stars, so the most-starred project is the Ace. "Deal again" re-deals the deck, and filters gather and re-deal it. Forks, archived repositories and repositories tagged `hide-from-site` are not listed and return 404.
- **Project pages:** Each project page opens with the project's business card, followed by its README, releases and recent commits. Market and betting projects show a "not investment or betting advice" note.
- **About & Links:** Each profile is a business card.
- **Contact:** A stationery-style form with a separate, explicit consent checkbox for sending the message through **Resend** (KVKK Art. 9). The consent is also checked on the server.
- **Legal:** A Privacy Policy and Terms of Use in both languages. The site uses no analytics or tracking cookies, so there is no cookie banner. Unknown URLs show a localised 404 card.
